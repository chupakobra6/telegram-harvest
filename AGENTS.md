# Telegram Harvest: работа с проектом

Локальный Go CLI для учебных чатов, личных дневных отчётов и полных приватных архивов зарегистрированных аккаунтов. Сбор читает Telegram. Узкие команды записи описаны ниже: self-доставка, организация завершённых рабочих диалогов, правка и публикация собственных материалов в закреплённом топике собеседований.

## Найти нужный контракт

- Команды, профили, авторизация и расположение данных — в [README](README.md). `main` и `study` используют соответственно `TG_HARVEST_DAILY_*` и `TG_HARVEST_STUDY_*`; дополнительные аккаунты заимствуют только API ID/hash, сохраняя отдельные сессию и привязку к числовому ID.
- Перед запросом «катчап» читай [docs/catch-up.md](docs/catch-up.md): стандартный `main daily-catchup` по вчерашний день, один проход диапазона, дневные источники и общий `00-latest-catchup.md`. Полный архив зарегистрированного аккаунта — отдельный явно запрошенный сценарий `account-sync`.
- Перед изменением сбора, состояния, пагинации, общих файлов или представлений читай [контракт полноты, восстановления и владения](docs/collection-integrity.md). `sync` дочитывает весь новый диапазон; период проверки старых правок задаёт потребитель через `--refresh-from`. Размер страницы ограничивает нагрузку, а подтверждённая граница — полноту.
- Перед изменением распознавания читай [ASR pipeline](README.md#asr-pipeline). Harvest владеет одним адаптивным профилем для Telegram, локальных файлов и OBS; стратегию выбирает по фактическому аудио. Пороги, модель и существенные настройки входят в идентичность кэша. При изменении семантики согласуй публичный контракт с `/Users/igor/projects/obs-interview-pipeline/internal/asr/runner.go` и его документацией.
- Перед изменением Telegram-транспорта читай [Telegram pacing](README.md#telegram-pacing) и [медиа и лимиты](README.md#медиа-и-лимиты). Сохраняй последовательного владельца истории и выбора медиа, два общих сетевых слота и исключение одновременной загрузки с history RPC. Локальная очередь `ffmpeg → ASR` работает независимо от Telegram-клиента.

## Доступ и приватность

- Указывай `--profile main|study|<зарегистрированное-имя>` явно; реестр `account add/list` работает без профиля. Охват study задаёт allowlist, если он настроен; дневной main сохраняет только self/исходящие и пары `chat_id:sender_id` из `TG_HARVEST_DAILY_ADDITIONAL_SENDERS`. Других участников этих чатов в daily не включай.
- Сессии, секреты, `.state/`, дампы, отчёты и представления остаются приватными и вне Git. Полные архивы входящих и исходящих сообщений зарегистрированных аккаунтов сохраняй вне репозитория. Хеши приложения, пароли, сессии и полные номера телефона не выводи.
- При `login` закрепляй числовой ID аккаунта; перед `account-sync` сверяй его с текущей сессией до записи. Обходи обычные и архивные диалоги последовательно, показывай неполный статус при сбое. Массовый архив по умолчанию сохраняет текст и метаданные без скачивания медиа и ASR.
- Для дополнительных аккаунтов используй отдельный `login` по номеру, коду Telegram и 2FA при необходимости. Не читай файлы или ключи Telegram Desktop; профили заимствуют только настроенные API ID/hash `main` или `study`.
- Организацию завершённых рабочих диалогов выполняй только по прямой просьбе Игоря через `account-organize --manifest <private.json> --apply`; без `--apply` действует dry-run. Контракт и точный manifest – [организация рабочих диалогов](README.md#организация-рабочих-диалогов). Допустимы только точные user peers выбранного зарегистрированного аккаунта, добавление в «Отработка» и архив ID 1. Сохраняй все прежние поля фильтра, include/pinned/exclude и сообщения; не снимай unread, не вызывай send/delete/join/pin. Сверяй свежий head до записи и перед каждым архивированием. `complete=true` требует серверного readback обоих изменений; частичные `server_verified` не означают завершение всего manifest. `account-folders` читает фильтры и выводит ID/порядок/настройки без access hashes.
- Правку уже опубликованных интервью выполняй только по прямому поручению через [interview-topic-update](README.md#правка-материалов-в-топике-собеседований). Назначение закреплено в коде: `main/@Pheik13` ID `1266978055`, супергруппа `2621478426`, топик `115` «Собеседования». Разрешены только тексты/подписи собственных сообщений и удаление собственных ZIP-постов `2348`, `2352` с проверенной локальной копией. Manifest приватный, dry-run действует до `--apply`; перед записью сверяй аккаунт, авторство, топик, полный hash текста и media ID. Сохраняй media/reply/topic; entities нового текста задавай явно, если прежние offsets перестают подходить. После действия нужен точный серверный readback. Новые send/upload, другие адресаты и mark-read сюда не входят.
- Новые собственные интервью в том же фиксированном топике публикуй только по прямому поручению через [interview-topic-publish](README.md#публикация-новых-интервью-в-закреплённый-топик). Manifest содержит точные постоянные post keys, текст/entities, родителей и локальные файлы/hash/metadata; максимум два новых текстовых родителя и их ответы. Dry-run не загружает и не отправляет; `--apply` использует детерминированные random IDs и приватный durable `<manifest>.receipts.json`. Не удаляй receipts и не меняй key ради retry: неизвестный исход без ID требует ручной сверки. Перед отправкой проверяй аккаунт, фиксированную группу/топик, собственного родителя и локальные байты; после – серверные sender/topic/reply/text/entities/filename/MIME/size и audio/video attributes. Полный manifest завершён только при `complete=true`; не используй живые сообщения как тест. Других получателей и произвольного send нет.
- Корректировку опубликованных скринингов audio→video выполняй по прямому поручению через [interview-topic-replace-video](README.md#замена-двух-аудиопостов-собеседований-на-видео). Разрешены только собственные ID `2362`→родитель `2361` и `2365`→родитель `2364` в том же фиксированном main-топике. Сохраняй ID/reply/topic; не создавай дубли, не удаляй другие посты или локальные исходники. Manifest фиксирует старые caption hash/media ID/audio metadata и новые MP4 hash/probe/caption/entities. Dry-run не загружает и не правит; apply использует приватные receipts, один edit RPC и точный readback. Unknown outcome не повторяй; уже новое video проверяй без новой записи. Исходный publisher manifest после замены устаревает, его receipts сохраняются как история.
- Отправляй через `send-saved` только по просьбе пользователя, профилем `main`, после проверки `@Pheik13`, исключительно в `InputPeerSelf` без аргумента адресата. Разрешение исходного чата для чтения видео не меняет получателя. Проверяй отправленное чтением из self-peer; для файла — имя, MIME-тип и размер; для видео — также исходные байты без перекодирования, подпись/entities, длительность, разрешение, аудиопризнак, streaming attribute и скачиваемое превью. Полная процедура — [отправка в «Избранное»](README.md#отправка-в-избранное). Другие операции записи, кроме явно перечисленных узких команд, не входят в инструмент.

## Данные и изменение кода

- Сохраняй в исходном JSONL чат, ID, дату, отправителя, текст и метаданные медиа, указатель на Telegram и раскрытое происхождение форварда. У форумов сохраняй `topic` и `thread_top_message_id`; название чата не заменяет идентичность темы. Markdown/TOON — пересобираемые представления, показывающие последнюю версию записи.
- Агент начинает с `agent-view/README.md`, затем выбирает `all-recent.md` либо чат/тему/день. При изменении этого пути согласуй генерируемые AGENTS и README. При изменении шаблонов или семантики манифеста подними `agentViewManifestVersion` и проверь rebuild/noop/incremental. `.agent-view-state.json` — приватное состояние обработанной позиции; вручную его не правь.
- Study `dump`/`sync` сохраняют доступные для просмотра изображения и документы при `--download-media`, без ASR. Daily и явно запрошенный main `dump` используют правила медиа/ASR из README. Временные аудио, видео, WAV и незавершённые расшифровки очищай при успехе, отказе и отмене; готовый кэш публикуй атомарно, одинаковые медиа в работе объединяй по ключу.
- Держи политику pacing, страниц и выбора ASR в коде; окружение задаёт доступ и локальные пути. При изменении CLI одновременно обновляй help, Makefile, README, применимые примеры `.env` и проверки команд. Предпочитай небольшие проверяемые функции авторизации, конфигурации, состояния, блокировок и обработки FloodWait; заменённые команды, профили и переменные удаляй вместе с вызывающими путями.

## Проверка и сохранение результата

- Установка закреплённых зависимостей – `make setup`; сборка – `make build`, форматирование – `make fmt`. `make check` – быстрый набор, `make audit` – статический и security-аудит, `make verify` – полная локальная проверка. GitHub Actions не используется. Make переиспользует бинарник до изменения Go/module-входов.
- Изменения Telegram-производительности принимай после сравнения на одинаковом корпусе: ключи сообщений, стабильное содержимое JSONL и медиа должны сохраниться, Telegram errors и FloodWait — отсутствовать. Проверяй парсинг, конфигурацию и состояние локально; живой Telegram — после авторизации в рамках порученного внедрения.
- При настройке закреплённого whisper.cpp проследи реальный путь параметра в установленном исходнике и проверь эффект сравнением на текущей сборке. Unit-тест передаваемого поля дополняй проверкой результата, который оно должно менять.
- Перед коммитом и push изменений Go-кода, зависимостей, Makefile или проверок выполняй `make verify` и указывай результат и оставшиеся ошибки в отчёте. Для правок только документации достаточно адресной сверки. Сохрани свои изменения коммитом и отправь текущую ветку в настроенный upstream. Постоянное разрешение пользователя на push действует; PR нужен по отдельной просьбе.
