# Telegram Harvest: работа с проектом

Локальный Go CLI для учебных чатов, личных дневных отчётов и полных приватных архивов зарегистрированных аккаунтов. Сбор читает Telegram. Отдельные команды поддерживают доставку в «Избранное», организацию завершённых рабочих диалогов, работу с собственными материалами в топике собеседований, отправку в печатный цех и явно разрешённые ответы в личных диалогах.

## Найти нужный контракт

- Команды, профили, авторизация и расположение данных — в [README](README.md). `main` и `study` используют соответственно `TG_HARVEST_DAILY_*` и `TG_HARVEST_STUDY_*`; дополнительные аккаунты заимствуют только API ID/hash, сохраняя отдельные сессию и привязку к числовому ID.
- Перед запросом «катчап» или «продолжи рекап до сейчас, текстом» читай [docs/catch-up.md](docs/catch-up.md): обычный `main daily-catchup` собирает завершённые дни; `daily-catchup --recap` готовит точный диапазон до момента запроса, включая голосовые и «Избранное», для личного текста в чате. Выдача источников не подтверждает выдачу рекапа. Полный архив зарегистрированного аккаунта – отдельный явно запрошенный сценарий `account-sync`.
- Перед изменением сбора, состояния, пагинации, общих файлов или представлений читай [контракт полноты, восстановления и владения](docs/collection-integrity.md). `sync` дочитывает весь новый диапазон; период проверки старых правок задаёт потребитель через `--refresh-from`. Размер страницы ограничивает нагрузку, а подтверждённая граница — полноту.
- Перед изменением распознавания читай [ASR pipeline](README.md#asr-pipeline). Harvest владеет одним адаптивным профилем для Telegram, локальных файлов и OBS; стратегию выбирает по фактическому аудио. Пороги, модель и существенные настройки входят в идентичность кэша. При изменении семантики согласуй публичный контракт с `/Users/igor/projects/obs-interview-pipeline/internal/asr/runner.go` и его документацией.
- Перед изменением Telegram-транспорта читай [Telegram pacing](README.md#telegram-pacing) и [медиа и лимиты](README.md#медиа-и-лимиты). Сохраняй последовательного владельца истории и выбора медиа, два общих сетевых слота и исключение одновременной загрузки с history RPC. Локальная очередь `ffmpeg → ASR` работает независимо от Telegram-клиента.

## Доступ и приватность

- Указывай `--profile main|study|<зарегистрированное-имя>` явно; реестр `account add/list` работает без профиля. Охват study задаёт allowlist, если он настроен; дневной main сохраняет только self/исходящие и пары `chat_id:sender_id` из `TG_HARVEST_DAILY_ADDITIONAL_SENDERS`. Других участников этих чатов в daily не включай.
- Сессии, секреты, `.state/`, дампы, отчёты и представления остаются приватными и вне Git. Полные архивы входящих и исходящих сообщений зарегистрированных аккаунтов сохраняй вне репозитория. Хеши приложения, пароли, сессии и полные номера телефона не выводи.
- При `login` закрепляй числовой ID аккаунта; перед `account-sync` сверяй его с текущей сессией до записи. Обходи обычные и архивные диалоги последовательно, показывай неполный статус при сбое. Массовый архив по умолчанию сохраняет текст и метаданные без скачивания медиа и ASR.
- Для дополнительных аккаунтов используй отдельный `login` по номеру, коду Telegram и 2FA при необходимости. Не читай файлы или ключи Telegram Desktop; профили заимствуют только настроенные API ID/hash `main` или `study`.
- Перед любой записью прочитай полный контракт подходящей команды ниже, включая manifest, проверки и обработку неизвестного исхода. `direct-reply` и `print-shop-publish` выводят полный preview и компактный apply-результат; `--details` возвращает полный apply JSON, без дополнительной обработки вывода. Прямое поручение определяет действие и получателя; `--apply` само по себе не является разрешением. При неизвестном исходе не повторяй отправку вслепую и не удаляй receipts: сначала сверь серверное состояние. Частичный успех не подтверждает весь manifest.

| Действие | Обязательный контракт и границы |
| --- | --- |
| Организация рабочих диалогов | [account-organize](README.md#организация-рабочих-диалогов): точные user peers зарегистрированного аккаунта, папка «Отработка» и архив; dry-run до `--apply`, свежие heads и серверный readback. `account-folders` только читает фильтры. |
| Правка опубликованных интервью | [interview-topic-update](README.md#правка-материалов-в-топике-собеседований): только собственные сообщения и разрешённые ZIP в закреплённом main-топике. |
| Новые интервью | [interview-topic-publish](README.md#публикация-новых-интервью-в-закреплённый-топик): только собственные материалы в закреплённом main-топике; сохраняй manifest, постоянные ключи и receipts. |
| Замена двух аудиопостов | [interview-topic-replace-video](README.md#замена-двух-аудиопостов-собеседований-на-видео): только закреплённые ID и родители; сохрани исходники и receipts. |
| Печатный цех | [print-shop-publish](README.md#отправка-в-печатный-цех): только согласованные текст, PDF и MP4 в фиксированной группе Игоря и Арины; проверяй состав и серверные байты. |
| Сообщение или нативный черновик | [message](README.md#сообщения-и-черновики): `main` или зарегистрированный профиль; конкретная отправка требует явного разрешения. `study` – только чтение. |
| Ответ человеку | [direct-reply](README.md#ответ-в-личном-диалоге): только конкретный разрешённый ответ на входящее сообщение от `main/@Pheik13`; журнал и серверная проверка обязательны. |
| «Избранное» | [send-saved](README.md#отправка-в-избранное): только `main/@Pheik13` и `InputPeerSelf`, по просьбе пользователя. Сверяй серверную копию; правила видео, native audio, fallback и readback – в полном контракте. |

Доступ к произвольному адресату не даёт разрешения на отправку: черновик по умолчанию возвращай в чат; нативный черновик сохраняй только по запросу. Не заменяй существующий черновик. Другие действия записи не разрешаются самим фактом доступа или выбора команды. Не используй живые сообщения как тест. Study остаётся источником для чтения; исходный чат для чтения не меняет получателя «Избранного».

## Данные и изменение кода

- Сохраняй в исходном JSONL чат, ID, дату, отправителя, текст и метаданные медиа, указатель на Telegram и раскрытое происхождение форварда. У форумов сохраняй `topic` и `thread_top_message_id`; название чата не заменяет идентичность темы. Markdown/TOON — пересобираемые представления, показывающие последнюю версию записи.
- Агент начинает с `agent-view/README.md`, затем выбирает `all-recent.md` либо чат/тему/день. При изменении этого пути согласуй генерируемые AGENTS и README. При изменении шаблонов данных или семантики манифеста подними `agentViewManifestVersion` и проверь rebuild/noop/incremental. Отдельную правку инструкции проверяй на обычном повторном `agent-view`: меняется только сгенерированный `AGENTS.md`, данные переиспользуются. `.agent-view-state.json` — приватное состояние обработанной позиции; вручную его не правь.
- Study `dump`/`sync` сохраняют доступные для просмотра изображения и документы при `--download-media`, без ASR. Для main `sync` с распознаванием используй [контракт sync ASR](README.md#sync-с-распознаванием-медиа), включая восстановление диапазона и проверку ошибок вложений. Daily и явно запрошенный main `dump` используют правила медиа/ASR из README. Временные аудио, видео, WAV и незавершённые расшифровки очищай при успехе, отказе и отмене; готовый кэш публикуй атомарно, одинаковые медиа в работе объединяй по ключу.
- Держи политику pacing, страниц и выбора ASR в коде; окружение задаёт доступ и локальные пути. При изменении CLI одновременно обновляй help, Makefile, README, применимые примеры `.env` и проверки команд. Предпочитай небольшие проверяемые функции авторизации, конфигурации, состояния, блокировок и обработки FloodWait; заменённые команды, профили и переменные удаляй вместе с вызывающими путями.

## Проверка и сохранение результата

- Установка закреплённых зависимостей – `make setup`; сборка – `make build`, форматирование – `make fmt`. `make check` – быстрый набор, `make audit` – статический и security-аудит, `make verify` – полная локальная проверка. GitHub Actions не используется. Make переиспользует бинарник до изменения Go/module-входов.
- Изменения Telegram-производительности принимай после сравнения на одинаковом корпусе: ключи сообщений, стабильное содержимое JSONL и медиа должны сохраниться, Telegram errors и FloodWait — отсутствовать. Проверяй парсинг, конфигурацию и состояние локально; живой Telegram — после авторизации в рамках порученного внедрения.
- При настройке закреплённого whisper.cpp проследи реальный путь параметра в установленном исходнике и проверь эффект сравнением на текущей сборке. Unit-тест передаваемого поля дополняй проверкой результата, который оно должно менять.
- Для локальной правки Go запускай тесты затронутых пакетов и проверяй изменённый сценарий. Перед коммитом и push изменений общих контрактов, зависимостей, Makefile или механизма проверок, а также перед выпуском выполняй `make verify`. Указывай пройденные проверки и оставшиеся ошибки в отчёте. Для правок только документации достаточно адресной сверки. Сохрани свои изменения коммитом и отправь текущую ветку в настроенный upstream. Постоянное разрешение пользователя на push действует; PR нужен по отдельной просьбе.
