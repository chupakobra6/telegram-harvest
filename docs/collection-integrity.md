# Полнота сбора

## Диапазон и нагрузка — разные ограничения

`sync` читает все новые сообщения после подтверждённой позиции. Общего `--limit` у него нет. `dump --all`, full backfill и account-sync не имеют общего лимита сообщений. Обычный `dump --limit N` — намеренная выборка: её вывод содержит `complete=false`, если граница истории не доказана. Размер одной history-страницы остаётся 100, пауза RPC — 500 мс, download budget — два chunk slots. `FLOOD_WAIT` соблюдается с ограниченным числом повторов; прерывание возвращает ошибку.

Короткая страница истории, диалогов или топиков не доказывает полноту. Обход продолжается до подтверждённой границы либо пустой страницы; неповторяющаяся позиция проверяется. Неполная или непригодная для продолжения выдача — ошибка, а не отсутствие данных.

Daily/catch-up по умолчанию перечисляет все доступные обычные и архивные диалоги, сохраняя прежний фильтр self/разрешённых дополнительных отправителей. Общего `--limit` у архивного daily нет: раньше он обрезал уже собранные записи перед публикацией и мог оставить полный checkpoint при неполном отчёте. Явный диагностический `--dialog-limit` делает результат неполным, если диалоги остались за границей; такой проход не подтверждает полный checkpoint. Для намеренной короткой выборки используются `dump` или `compact`.

## Сохранение и восстановление

Инкрементальная загрузка пишет страницы в приватный `.incremental.jsonl` и fsync-журнал рядом со state. На границе страницы сохраняются размер staging и следующая позиция. После отмены обычный `sync` продолжает эту загрузку, включая начатую сверку старых сообщений. Незафиксированный хвост staging отбрасывается и перечитывается; рабочие JSONL до завершения диапазона не меняются.

После полного чтения журнал фиксирует размеры выходных файлов. Публикуется точный suffix, файлы синхронизируются, затем атомарно сохраняется state. Повтор после частичной публикации не дублирует suffix; неожиданное содержимое от другого writer вызывает ошибку. Runtime-lock обязателен для всех CLI-писателей профиля. Файлы незавершённой загрузки нельзя вручную удалять ради обхода ошибки.

`sync --all --reset` остаётся явным началом полного backfill; `sync --all` продолжает его. Неполный результат не выдаётся за завершение. Существующий архив не сбрасывается при обычном восстановлении.

## Правки уже полученных сообщений

Новый ID и изменение старого сообщения — разные сигналы. Для заданного периода:

```bash
bin/telegram-harvest --profile study sync --chat <chat> --name <stream> \
  --refresh-from 2026-09-01 --merged-out messages.jsonl --download-media
```

Проход читает весь период без лимита записей, добавляет отсутствующие сообщения и смысловые изменения, не повторяя неизменившиеся. Метаданные unread/head/views/cache не считаются изменением учебного текста. Версия хранится в append-only JSONL с `revision`; старые версии не удаляются. Agent-view при ревизии пересобирается с последней версией каждого ID; compact также исключает устаревшие версии. Время редактирования сохраняется, если его прислал Telegram.

Обычный ID-sync сам по себе не обещает обнаружить правку произвольно старого сообщения. Период регулярной сверки задаёт вызывающий проект. Удаления и сообщения, к которым Telegram уже не даёт доступа, не восстанавливаются из отсутствия ID.

## Регрессии

Проверяются 250/6000 новых сообщений при прежнем cap 100, отмена после fsync страницы с частично записанной следующей, новый head во время продолжения, короткая/повторная страница, ограниченный preview, 601 диалог, правка старого текста и пропущенный старый ID, повтор сверки без дельты и отсутствие старой версии в представлениях. Перед выпуском — `make verify` и scoped live-проверка действующего бинарника. Успех синтетических тестов не доказывает полноту всей прошлой истории.
